# PDF 与图像证据处理规范

本规范用于 `$legal-case-workflow` 中的 PDF、扫描件、图片和聊天截图处理。原始材料始终保留在 `00_source/`，本规范生成的全部结果必须写入衍生目录。

## 1. PDF 处理顺序

1. 识别真实文件类型并取得 PDF 页数，不能只信扩展名。
2. 检测是否存在原生文本层。
3. 抽样检查文本层质量：逐页字符数、大量乱码、阅读顺序、页码错位、表格破坏。
4. 原生文本可靠时，直接按页提取，并保留页级边界。
5. 影像型 PDF 或文本层不可用时才执行 OCR。
6. OCR 仅生成衍生文件，禁止覆盖或回写原 PDF。
7. 页面图像或原始截图是视觉核验依据；OCR 文本不能替代视觉载体。
8. 每页 Markdown 标明材料编号与 PDF 页码。
9. 原书页码与 PDF 页码并存时分别记录，如“PDF 第 12 页；原页码 8”。
10. 表格、印章、签名、指印、手写内容及关键版式保留页面图像引用。

文本层检测只能说明“可能存在”或“未检测到”，不能单凭少量字符判定全文可靠。可靠性抽样至少覆盖首页、中间页、末页及包含表格或印章的关键页；抽样结论和异常页记入 `99_audit/`。

## 2. OCR 原文、规范化与视觉复核

以下字段必须回看原始页面或原始截图：

- 姓名、公司名称、机关名称；
- 身份证号、银行账号、电话号码；
- 日期、时间、金额、小数点、币种；
- 条款编号、页码、否定词；
- 签字、指印、印章、手写补充；
- 交易流水号、转账附言。

OCR 原始结果和规范化结果分别保存，不得静默替换。字段记录至少包含：

```json
{
  "field": "payment_amount",
  "raw_text": "¥230,000.00",
  "normalized_value": 230000,
  "source_id": "DOC-004",
  "location": "PDF page 7",
  "verification_status": "visual_verified",
  "confidence": "high"
}
```

`verification_status` 未达到 `visual_verified` 时，不得把高风险字段写成已核事实。无法确认时标注“待核对”，同时保留 OCR 原文及页面定位。

## 3. 超长聊天截图

- 不得把整张长图缩小后直接识别。
- 每片建议高度 1600 至 2200 像素，相邻切片保留约 15% 重叠。
- 文件名同时记录材料编号、原图标识和纵向坐标，例如 `DOC-012__chat__y000000-y001900.png`。
- 原图不得重新压缩、裁切或覆盖；切片写入 `02_readable/`。
- 合并聊天文本时，依据时间、发送者、文本和重叠区域去重，并保留切片坐标引用。
- 无法确认发送者、时间或消息归属时，标为“待核对”，不靠上下文猜测。

## 4. 缓存与增量处理

缓存键至少包含：

```text
源文件 SHA-256
+ 转换脚本版本
+ OCR 工具版本
+ 处理参数版本
```

文件哈希和缓存键均未变化时，不重复解压、页面渲染、OCR、截图切片、全文提取或已完成的结构化抽取。工具版本或参数改变时，新结果写成可区分版本，不覆盖旧衍生结果。

## 5. 失败与能力缺失

- 缺少 `pypdf`、Pillow、`pdfinfo`、`pdftotext` 或 `ocrmypdf` 时，记录 `capability unavailable`，不得假报成功。
- 转换失败时保留原始材料，记录命令、退出码、失败文件、未完成范围和建议的人工处理方式；日志不得泄漏不必要的个人信息。
- 任何可搜索 PDF、Markdown、OCR JSON 或截图切片都只是衍生物，最终引用与关键字段必须回到原始页或原始截图核验。
