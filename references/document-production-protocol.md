# 法律文书制作协议

本协议用于把案件事实、模板结构、语言状态和排版验收分开控制。涉及 DOCX 的任务必须先完成本页所列的四项路由。

## 1. 四项路由

### 1.1 使用目的

- `formal-final`：可签署、提交或对外发送的正式版本。
- `formal-draft`：供律师审阅的准正式草稿。
- `internal-analysis`：仅用于事实核验、问题追踪或团队讨论。

只有内部文件可以保留核验标记、证据缺口、处理说明或技术过程语言。

### 1.2 文书包范围

- `requested-only`：只做用户点名的文件，默认值。
- `filing-core`：当前申请通常必需的核心文件。
- `filing-complete`：用户确认后的完整办理包，包括必要配套文件。

参考包中存在某文件，不等于本次自动需要制作该文件。

### 1.3 设计权威

按以下优先级选择：本次明确要求 > 当前机关表格或用户模板 > 已批准律所模板/规范 > 已选版本画像 > 通用基线。

版本画像只证明“怎样排版或组织”，不证明“应当填写什么事实”。

### 1.4 编辑强度

- `fill-only`：默认。保留表格、条款、编号、选项、签署区和附件清单，只填充有证据支持的字段。
- `rewrite-authorized`：用户明确允许结构性改写后使用。

以下动作属于结构性改写：删除或合并条款、删除收费选项、改变权利义务、重编号、改变表格行列、改变授权范围、缩减附件清单、重做签署区。

## 2. 模板画像应记录的字段

每个可复用画像至少记录：

- `profile_id`、来源路径、采样日期、适用机构与适用文书；
- 页面尺寸、页边距、页面方向、预计页数；
- 标题、正文、编号、落款的字体与字号；
- 段前段后、行距、首行缩进、制表位和对齐方式；
- 表格行列、列宽、边框、单元格边距、合并方式；
- 页眉页脚、图片、Logo、页码和签署区；
- 固定措辞、编号体系、附件结构；
- 已知冲突、例外和禁止自动继承的事实字段。

画像参数必须来自可检查的 DOCX 结构或逐页视觉观察。不要凭肉眼印象把近似值写成精确规范。

## 3. 正式语言与内部语言分离

正式签署版不得出现：

- `【待确认】`、`【待填写】`、`【待核对】` 等内部占位标记；
- “传票载”“未提供可供核验”等来源说明；
- OCR、哈希、模型、脚本、解析失败、内部审阅等过程语言；
- 与当前模板不一致的旧地址、旧人员、旧编号或旧日期。

缺失字段在正式版中使用模板允许的空白线、空格或留空；其核验状态写入独立待核表。

语言风格原则：

1. 固定文书继承当前模板的句式、称谓和编号体系。
2. 不因追求简洁擅自删除限定语、权利保留、责任条款或收费选项。
3. 不因追求“现代化”擅自把中文层级编号改为十进制编号，反之亦然。
4. 分析文书可以呈现证据强弱和争议；正式文书只呈现其用途所需的结论与请求。

## 4. 律所常量与案件变量

律所常量必须进入集中登记表，每项包括：字段值、来源、`verified_at`、状态和适用范围。出现两个版本时不得静默选择。

以下永远视为案件变量，不能写死在通用 Skill：当事人、证件号、案号、金额、银行账号、联系方式、签约日期、代理权限、律师组合、收费选择、利息截止日。

律所收款账户与当事人收款账户必须分开命名和核对。

## 5. 动态字段刷新

最终渲染后重新核对：

- 文书签署日、出具日、案号年度；
- 利息或迟延履行金的截止日与计算说明；
- “共几页”“附件几份”等页数描述；
- 页码、目录、交叉引用、表格续页标题；
- 文档属性中的页数与实际可见页数差异。

## 6. 结构检查

至少检查：

- DOCX 压缩包和 XML 可解析；
- 页面尺寸、方向、页边距与分节设置；
- 字体、字号、缩进、行距、段前段后和制表位；
- 表格行列、合并单元格、列宽、边框和单元格边距；
- 图片、页眉页脚、页码和签署区；
- 全文禁用语、旧值、重复字段和跨文书矛盾；
- 文件名、文书标题和交付清单一致。

## 7. 视觉检查

将 DOCX 转为 PDF 或逐页图片，检查：

- 标题层级、留白和正文密度是否接近权威模板；
- 表格是否溢出、跨页断裂或形成大面积异常空白；
- 是否存在孤行、孤页、单字成行或签署区被挤到下一页；
- Logo、页眉、页脚、页码、签名线与盖章位置是否正确；
- 字体替换是否导致分页变化；
- 页面总数是否与文书中的文字描述一致。

结构检查和视觉检查是两道独立门，不能互相替代。

## 8. 交付与版本门

交付目录应包含本次明确要求的文件，不夹带草稿、转换临时文件或旧版本。正式交付前：

1. 保存原模板和修改前回滚版；
2. 生成最终文件 SHA-256；
3. 记录模板或画像版本、验收日期和验收结果；
4. 重新计算哈希，确认验收后文件未再变化；
5. 把待核字段和未通过项单独列出，不藏入签署版。
